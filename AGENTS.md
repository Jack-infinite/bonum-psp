# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

This is a pnpm monorepo with three deliverables for **Bonum PSP V2** (asynchronous Apple Pay and
Google Pay payments with webhooks). It is an **unofficial** project, not affiliated with BONUM LLC.

- `packages/sdk`: **`bonum-psp`**, the server-side TypeScript SDK. Zero runtime dependencies.
- `packages/mcp`: **`bonum-psp-mcp`**, an MCP server over stdio (binary `bonum-psp-mcp`, server
  name `bonum`).
- `skills/bonum-psp-integration/SKILL.md`: an Agent Skill for Claude Code and Codex.

## Commands

Develop on Node 26 (`.nvmrc`) with pnpm 12. The `packageManager` field pins the exact version.
Both packages support Node `>=22.12.0`.

| Command                                              | What it does                                                                           |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `pnpm install`                                       | Install everything (use `--frozen-lockfile` in CI)                                     |
| `pnpm check`                                         | **Run before every commit:** lint, build, typecheck, test with coverage, publint, attw |
| `pnpm build`                                         | Sync `version.ts` from each `package.json`, then build both packages with tsdown       |
| `pnpm test`                                          | Vitest with v8 coverage, both packages                                                 |
| `pnpm exec vitest run packages/mcp/test/env.test.ts` | One test file                                                                          |
| `pnpm typecheck`                                     | `tsc` per package; the SDK's `src` is also checked without Node types                  |
| `pnpm lint`                                          | `biome check .` and `knip` (unused files, exports, dependencies)                       |
| `pnpm format`                                        | `biome check --write .`                                                                |
| `pnpm lint:packages`                                 | `publint --strict` and `attw --pack --profile esm-only` per package                    |
| `pnpm changeset`                                     | Describe a user-facing change for the next release                                     |

The MCP smoke test (`packages/mcp/test/smoke.test.ts`) spawns `packages/mcp/dist/cli.js`. Run
`pnpm build` before testing (`pnpm check` does).

## Architecture

```
packages/sdk/src
├─ index.ts              the only barrel: public exports
├─ client.ts             BonumClient: config + payments + lazy `webhooks`
├─ config.ts             options, env fallbacks, base URLs, validation, frozen config
├─ runtime.ts            readEnv() over globalThis.process, browser guard
├─ http.ts               fetch wrapper: headers, timeouts, retries, redirect: 'manual'
├─ retry.ts              backoff with full jitter, Retry-After
├─ errors.ts, api-errors.ts   BonumError hierarchy with stable `code`s
├─ payments.ts           the five V2 endpoints
├─ params.ts             request parameter types
├─ responses.ts          minimal shape checks on 2xx bodies
├─ fields.ts             typed field reader used by the response parsers
├─ validation.ts         hand-written validators (no schema library)
├─ wallet-tokens.ts      Apple Pay / Google Pay token checks
├─ types.ts, currency.ts public types, `as const` objects, normalizeCurrency()
├─ version.ts            generated by scripts/sync-version.mjs, committed
├─ webhooks/             BonumWebhooks, signature (Web Crypto HMAC), event parsing,
│                        case-insensitive headers, the Fetch handler
├─ express.ts            subpath `bonum-psp/express` (structural types, no express dependency)
└─ testing.ts            subpath `bonum-psp/testing`: test events and signing

packages/mcp/src
├─ cli.ts                bin: parse args → depsFromEnv(process.env) → serveStdio
├─ args.ts               --help / --version
├─ env.ts                depsFromEnv(): env → deps, never throws, collects warnings
├─ deps.ts               BonumMcpServerDeps and defaults
├─ server.ts             createBonumMcpServer(deps): a pure factory
├─ redact.ts             secret redaction applied to every tool output
├─ webhook-toolkit.ts    verify + sign with the configured secret (kept in a closure)
├─ tools/                one file per tool, plus shared tool.ts, schemas, webhook delivery
├─ resources/            guides as TypeScript modules exporting Markdown strings
└─ prompts/              integrate_bonum, debug_webhook, review_bonum_integration
```

Data flow in the SDK: `BonumClient` → `Payments` → `HttpClient` → `fetch`. Every URL is built from
the configured base URL plus a validated `paymentId`. URLs that Bonum returns are never called.
Webhooks: raw bytes plus headers → `parseSignatureHeaders` → timestamp check → HMAC verify →
`JSON.parse` → `parseWebhookEvent`.

In the MCP server, every tool is registered through `tools/tool.ts`. It catches all errors
(otherwise the MCP SDK would return raw messages unredacted) and redacts text and
`structuredContent`. It also adds the production banner to tools that call Bonum.

## Rules

These are the project's standards; [CONTRIBUTING.md](./CONTRIBUTING.md) covers setup. Follow them
in every change.

**TypeScript**

- TypeScript 7, `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch`. Use `module`/`moduleResolution` `nodenext`
  and target ES2023.
- `verbatimModuleSyntax`, `erasableSyntaxOnly` (no `enum`, `namespace` or parameter properties),
  `isolatedDeclarations` (explicit types on exports).
- List `types` explicitly. SDK `src` compiles **without** `@types/node` (`lib`: ES2023, DOM,
  DOM.Iterable), so Node-only APIs cannot sneak in. Tests and the MCP package use `types: ["node"]`.
- Declare public optional properties as `prop?: T | undefined`.
- No `any` (use `unknown` and narrow), no non-null assertions, no `enum`. Use string-literal unions
  plus `as const` objects (`PaymentStatus.AUTHORIZED`).

**Code**

- Named exports only (config files excepted). One concept per file: aim for files under 200 lines
  and functions under 40.
- Prefer pure functions. Inject side effects (`fetch`, `now`, `sleep`, `random`) through options, so
  tests are deterministic.
- Every public export has TSDoc with a one-line summary and an `@example` (`test/docs.test.ts`
  checks this).
- Errors are specific classes with a stable `code` and a `cause`. Messages say what to do next.
- Comments explain _why_, not _what_.

**Secrets and output**

- Libraries never `console.log`. The MCP server logs to **stderr** only; stdout is the JSON-RPC
  channel.
- Secrets never appear in errors, logs, `toString()`, `toJSON()` or `util.inspect` output. Keep
  them in `#private` fields or closures.
- MCP: secrets come only from the environment, never from tool arguments, and every output goes
  through `redact()`.
- Never commit, print or use as a fixture a real merchant key or webhook secret. Use obviously fake
  values: `mk_test_example`, `test_webhook_secret`. MCP tests use `mk_test_mcp_suite` and
  `test_secret_mcp_suite`, and scan every output for them.

**Dependencies and packaging**

- The SDK has **zero** runtime `dependencies`, and only Web-standard APIs: `fetch`, Web Crypto,
  `AbortSignal`, `TextEncoder`.
- ESM only. tsdown emits `.js`, `.d.ts` and sourcemaps; dependencies are never bundled.
- Check current versions with `npm view <pkg> version` before adding or bumping a dependency.

**Bonum documentation**

- Bonum's pages carry a confidentiality notice. **Never copy their text** into this repository.
  Write in your own words and link to <https://psp.bonum.mn/v2/>. Field names, paths and the signing
  algorithm are facts and fine to use.
- Where Bonum's docs are ambiguous, take the safer option and record it in
  [`docs/decisions.md`](./docs/decisions.md), one short paragraph per decision. Read that file
  before changing behavior; it explains choices that may look odd (for example, `redirect: 'manual'`).

**Tests**

- Vitest 5. Coverage thresholds: SDK ≥ 95 % lines and ≥ 90 % branches; MCP ≥ 85 % lines.
- Webhook tests compute expected signatures with `node:crypto` `createHmac`, an independent
  implementation, never with the SDK's own signer.
- `packages/sdk/test/sandbox.test.ts` runs only when `BONUM_SANDBOX_MERCHANT_KEY` is set, and never
  touches real payments.

**Workflow**

- `pnpm check` must be green before a commit. Never build on a red check.
- Use Conventional Commits with scopes such as `sdk`, `mcp`, `skill`, `docs`, `ci` and `deps`.
- Add a changeset (`pnpm changeset`) for every user-facing change to a published package.
- A document with a Mongolian copy (`X.mn.md` next to `X.md`) gets every change in both files.
  Code blocks stay identical; only the prose is translated.
